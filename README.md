# FocusFlight Web

A focus timer that flies. Pick a departure and an arrival airport; the route's
flight time becomes your focus session, and a plane crosses a dark, warm-toned
map on the great-circle route until the session ends. Built for full-screen use
on a desktop monitor, and it also works on a phone.

**Live:** https://focusflight-web-gamma.vercel.app

## How it works

- **Flight time** is the great-circle distance at a fixed 800 km/h block
  speed: HKG → LHR is 9,630 km, which is 12 h 2 m. Routes under 150 km are
  too short to fly.
- **Speed** scales the session from 0.25× to 10×. At 2× the session takes half
  the time, and at 0.5× it takes twice as long. You can change it mid-flight:
  the plane stays where it is and the remaining time is recomputed.
- **Pause** stops the clock, and paused time does not count as focus time.
  **End flight** needs a second click to confirm, and the flight is logged as
  aborted.
- **Arrival** plays a short chime, shows the time you focused, and logs the
  flight.
- **Logbook** lists every flight, newest first, with total focus time, the
  distance of the flights that landed and how many landed.
- **Nothing leaves your browser.** Flights, the logbook and settings live in
  `localStorage` (`ffw.*` keys). There are no accounts, no backend and no
  tracking. If you close the tab mid-flight, reopening it resumes the flight
  at the right point, because the time the tab was closed still counts.

## Keyboard shortcuts

| Key     | Action                                                      |
| ------- | ----------------------------------------------------------- |
| `F`     | Toggle full screen (also the ⤢ button, top right)           |
| `Space` | Pause / resume, in flight                                   |
| `Esc`   | Leave full screen (browser default)                         |

In flight, the HUD fades out after 3 seconds without mouse movement and comes
back when you move the mouse or press a key. Everything respects
`prefers-reduced-motion`.

## Run locally

Needs Node 22.12 or newer (Vitest 5's minimum; Vercel builds on Node 24).

```sh
npm install
npm run dev       # dev server at http://localhost:5173
npm test          # vitest, single run
npm run build     # production build into dist/
npm run preview   # serve dist/ locally
```

## Deploy

The site is fully static and has no environment variables or secrets.

On Vercel: **Add New → Project**, import the GitHub repo, pick the **Vite**
framework preset (build command `npm run build`, output directory `dist`),
and deploy. Every push to `main` then deploys to production, and other
branches get preview URLs.

Any static host works the same way: run `npm run build` and serve `dist/`.

## Project layout

```
src/lib/      pure logic: geo maths, flight engine, storage, screen models (unit-tested)
src/ui/       DOM and canvas: map renderer, boarding pass, HUD, arrival, logbook
src/styles/   CSS with custom properties only (tokens.css holds the palette)
src/data/     airports.json, generated by scripts/build-airports.mjs
test/         vitest suites
```

Regenerate the airport list with `node scripts/build-airports.mjs`. It
downloads OurAirports' `airports.csv` and keeps large airports that have an
IATA code.
